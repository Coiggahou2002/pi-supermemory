# Readable capture and honest extraction status

- Root cause verified on a real captured document: source `status=done`, memory `dreamingStatus=dreaming`, zero memories. Dynamic generation may lag searchable source ingestion by minutes. Do not describe acceptance/searchability as completed memory extraction, or assume JSON itself prevented extraction.
- New batches use deterministic readable Markdown: a short heading derived from the first user text, explicit User/Assistant sections, and blockquoted source text. Internal schema/version tags stay in metadata rather than visible content. Keep privacy filtering and whole-payload limits unchanged.
- Persist batch format and processing mode in the metadata-only journal. Missing fields mean legacy JSON-v1 + dynamic, so pending v0.3/v0.4 work reconstructs the exact original ID/content. Do not rewrite old remote documents or replay accepted history on upgrade.
- Stop writing the generic extraction instructions into `supportingContext` on every new capture: this field is namespace-wide, and appeared as an ugly namespace description in the user's screenshot. Existing namespace settings are not automatically overwritten. New documents carry a title hint in metadata and a readable first heading; service-side title generation is not guaranteed to use the hint verbatim.
- Dynamic remains the default: no silent cost change. Explicit `/supermemory capture mode instant` shows confirmation that each document costs one extra operation. Environment `PI_SUPERMEMORY_CAPTURE_MODE=instant` is an explicit unattended choice. Snapshot mode per run and retain original mode on retries; toggles affect future runs only.
- Add `/supermemory capture status`, a bounded read of the latest accepted batch for the current session/namespace/authorization grant. Show source status, memory-generation status, derived-memory count and pending-batch count, never raw content. No automatic polling/network lookups on ordinary `/supermemory status` or every captured turn.
- Tests: readable Unicode/multiline content, exact legacy byte/ID reconstruction, mode persistence and retry stability, malformed/mismatched status responses, meaningful zero-memory/dreaming/done/failure labels, user confirmation before extra cost, SDK request contracts, and real Pi lifecycle integration. Live acceptance must check both source and memory stages in a disposable namespace; disclose delays or failures rather than calling an unfinished run successful.
