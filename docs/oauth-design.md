# OAuth implementation contract

- Default: explicit `/supermemory login`, browser Authorization Code + PKCE S256, random state, loopback callback. No browser or network auth from the extension factory or ordinary recall/tool calls.
- Use `openid-client` for discovery, DCR, code exchange, token validation, refresh, and revocation. Production issuer and resource are fixed to the official API issuer and hosted MCP resource used by the official agents. Endpoint origin checks and redirect rejection prevent credential forwarding elsewhere.
- Credentials live under Pi's agent directory in `supermemory/oauth.json`. Dedicated directory mode 0700, file mode 0600 on POSIX, atomic replace and fsync. Validate untrusted stored JSON. Never print tokens, callback codes, or raw OAuth errors.
- `proper-lockfile` serializes login, refresh, and logout across Pi processes. No process-local token cache: reread after acquiring the lock. Bounded lock waits and HTTP deadlines, heartbeat, and ownership checks before write. A network response lost during refresh can require reauthentication; never retry a potentially rotated refresh token automatically.
- Login timeout, denial, invalid state/issuer, occupied port, cancellation, and shutdown must close the listener. Wrong-state requests do not consume a valid login. Callback is GET on exact loopback Host/path and is single-use. No authorization response is reflected into HTML.
- Refresh is shared within a process and shielded from individual caller cancellation; rotated credentials are saved before returning. Shutdown awaits in-flight refresh. Access tokens are refreshed before expiry. invalid_grant/invalid_client invalidate local login and require explicit reauthentication.
- Logout attempts remote refresh-token revocation, then clears local credentials even if revocation is unavailable, reporting that limitation. All operations hold the same lock so an old refresh cannot recreate logged-out state.
- Optional environment API key remains an explicit override; `/supermemory login` explains that it must be unset before OAuth can be the active mode. Logout cannot revoke/unset an environment key.
- Default memory routing applies while the extension is loaded, including before login: unauthenticated saves instruct login instead of silently using local Markdown. Automatic query sharing remains opt-in; write confirmation remains unchanged.
- Offline tests cross the real library HTTP and loopback boundaries: DCR, state/PKCE, code, refresh rotation, multi-instance contention, malformed/missing storage, cancellation, timeout, revocation failures, reopen, file permissions, and authenticated SDK requests. Live browser consent and real REST access are a separate acceptance check with the user; no remote memories are written without consent.
