# Automatic capture contract

## Default behavior, disclosure and payload

- Since v0.4.0, on by default at the product owner's request: signing in should make new conversations become memories without a separate enable step. Startup clearly discloses remote user/final-answer uploads, possible billing, private-marker limitations, and opt-out controls before any user message. This also applies to headless use (stderr disclosure). No consent modal gates the default behavior; this is a deliberate change from v0.3.0.
- `/supermemory capture off` stops the current instance. `PI_SUPERMEMORY_AUTO_CAPTURE=false` is the persistent opt-out; session commands reset on reload. Explicit re-enable in the UI still shows confirmation. Manual fact writes retain confirmation; recall retains its independent opt-in. Retrying pending batches is an explicit resend operation, not an automatic backlog drain.
- No history backfill. `before_agent_start` records the current branch leaf BEFORE Pi persists the new user message. `agent_settled` captures only entries appended after that boundary. Custom-message starts, aborted/failed/incomplete runs, changed branches, and runs begun while disabled/signed out are not captured.
- Exclude system prompts, tools/results, assistant thinking/tool-calling responses, injected recalls, images, and extension state. If ANY source user/assistant/tool text in the run contains an opening/closing `<private>` marker, skip the whole run, including assistant echoes. This is not secret detection or protection against later unmarked paraphrases.
- Bound the complete serialized payload to 32 KB UTF-8. Oversize runs are visibly skipped, not silently truncated. New v2 source is readable Markdown with a heading, quoted speaker sections, and a reminder that assistant statements alone are not user preferences. Metadata carries a title hint/format. Namespace-wide supportingContext is not overwritten. Extraction quality remains service-dependent.

## Durability and identity

- Each batch has a deterministic document ID from schema version, namespace, session ID, authorization binding, source entry IDs, content digest and (for v2) processing mode. OAuth binding hashes issuer/resource/client ID for the explicit login grant, and survives token refresh; API-key mode binds the key fingerprint. Pending work cannot cross re-login/account changes. The SDK credential resolver rechecks this binding against the exact token it will use, preventing a concurrent login from redirecting uploads. The exact batch uses that same ID/content on every retry. v5 supports caller-defined IDs and append/diff deduplication; do not claim exactly-once extraction or billing after lost responses.
- A private, atomic JSON journal under the Pi agent directory stores ONLY session identity, namespace, source entry IDs, content digest, format, processing mode, pending/accepted state and acceptance receipt. Missing format/mode fields are legacy JSON-v1/dynamic for exact pre-upgrade retry compatibility. No transcript copies, tokens, paths, or raw errors are journaled. Use `proper-lockfile` to serialize competing senders across processes, and validate JSON before use.
- Prepare pending state before making the network call. Mark accepted only after a valid receipt echoes the requested ID. A network failure, invalid receipt, interrupted process, or failed local checkpoint leaves a stable pending operation. A restarted process can reconstruct it from the current session's raw branch using the exact IDs and digest.
- No detached worker or unsolicited historical resend on restart. `/supermemory capture retry` explicitly retries pending batches for the current namespace/session/active branch with consent; missing/edited/private sources are refused. Successful batches are not resent. Retry budget and limits are bounded. Ordinary runs do not repeatedly hammer a failed service.
- A generation fence prevents off/on races during asynchronous run preparation from reviving an older run. Off/logout/shutdown stop future capture and wait for current capture work; cancellation cannot retract a request already accepted by the server. No credential refresh or upload is abandoned on shutdown. Journal corruption/identity mismatches fail closed and are reported, not treated as an empty history.

## Processing stage and cost

- Dynamic generation is the default. Searchable source `done` does not mean memory `dreamingStatus` is done; a new namespace may stay at zero memories for minutes. `/supermemory capture status` explicitly reads the latest accepted batch's two stages and memory count; ordinary capture/status does not poll.
- Optional instant mode requires an explicit extra-operation-per-document confirmation in the UI, or the dedicated environment setting. Snapshot mode per run and persist it for retries. New formats or current mode settings never reinterpret pending old requests. See capture-format-v2.md.

## Verification and release

Tests cross actual Pi run/message/session/compaction boundaries and real SDK serialization. Cover default-on/disclosure/opt-out/history windows, multiple tool turns, private echoes, filtering, bounded payloads, aborts/errors/custom starts, duplicate settled events, pending retry, response loss, mismatched receipts, journal reopen/corruption, branch/namespace/session isolation, and competing processes/instances. Keep automatic extraction and real account billing explicit acceptance checks. Release a new pinned preview tag only after CI passes; never move v0.2.0.
