# Automatic capture contract

## Consent and payload

- Off by default. `/supermemory capture on` explicitly authorizes automatic remote ingestion of future user text and completed assistant answer text in the current extension instance; interactive consent explains this and possible billing. The independent `PI_SUPERMEMORY_AUTO_CAPTURE=true` environment setting is unattended/startup opt-in. Recall and manual-write settings do not enable capture.
- No history backfill. `before_agent_start` records the current branch leaf BEFORE Pi persists the new user message. `agent_settled` captures only entries appended after that boundary. Custom-message starts, aborted/failed/incomplete runs, changed branches, and runs begun while disabled/signed out are not captured.
- Exclude system prompts, tools/results, assistant thinking/tool-calling responses, injected recalls, images, and extension state. If ANY source user/assistant/tool text in the run contains an opening/closing `<private>` marker, skip the whole run, including assistant echoes. This is not secret detection or protection against later unmarked paraphrases.
- Bound the complete serialized payload to 32 KB UTF-8. Oversize runs are visibly skipped, not silently truncated. Content has explicit speaker roles; supportingContext asks the service to extract durable user-stated preferences, confirmed decisions and lessons, not assistant guesses or transient state. Extraction quality remains service-dependent.

## Durability and identity

- Each batch has a deterministic document ID from schema version, namespace, session ID, authorization binding, source entry IDs, and content digest. OAuth binding hashes issuer/resource/client ID for the explicit login grant, and survives token refresh; API-key mode binds the key fingerprint. Pending work cannot cross re-login/account changes. The SDK credential resolver rechecks this binding against the exact token it will use, preventing a concurrent login from redirecting uploads. The exact batch uses that same ID/content on every retry. v5 supports caller-defined IDs and append/diff deduplication; do not claim exactly-once extraction or billing after lost responses.
- A private, atomic JSON journal under the Pi agent directory stores ONLY session identity, namespace, source entry IDs, content digest, pending/accepted state and acceptance receipt. No transcript copies, tokens, paths, or raw errors are journaled. Use `proper-lockfile` to serialize competing senders across processes, and validate JSON before use.
- Prepare pending state before making the network call. Mark accepted only after a valid receipt echoes the requested ID. A network failure, invalid receipt, interrupted process, or failed local checkpoint leaves a stable pending operation. A restarted process can reconstruct it from the current session's raw branch using the exact IDs and digest.
- No detached worker or unsolicited historical resend on restart. `/supermemory capture retry` explicitly retries pending batches for the current namespace/session/active branch with consent; missing/edited/private sources are refused. Successful batches are not resent. Retry budget and limits are bounded. Ordinary runs do not repeatedly hammer a failed service.
- A generation fence prevents off/on races during asynchronous run preparation from reviving an older run. Off/logout/shutdown stop future capture and wait for current capture work; cancellation cannot retract a request already accepted by the server. No credential refresh or upload is abandoned on shutdown. Journal corruption/identity mismatches fail closed and are reported, not treated as an empty history.

## Verification and release

Tests cross actual Pi run/message/session/compaction boundaries and real SDK serialization. Cover opt-in/off/history windows, multiple tool turns, private echoes, filtering, bounded payloads, aborts/errors/custom starts, duplicate settled events, pending retry, response loss, mismatched receipts, journal reopen/corruption, branch/namespace/session isolation, and competing processes/instances. Keep automatic extraction and real account billing explicit acceptance checks. Release a new pinned preview tag only after CI passes; never move v0.2.0.
